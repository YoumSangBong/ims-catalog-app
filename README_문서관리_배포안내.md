## 이번에 반영된 내용 (1~7번)

1. **storage 폴더 6분류**를 실제 GCS 경로로 매핑(`scripts/storage_paths.py`) — 통합본/
   매뉴얼·절차서/매뉴얼·절차서(내용본)/양식/지침서/지침서(내용본).
2. **GCS 버킷·서비스계정 연동**은 이미 완료해두신 대로 그대로 사용합니다
   (`scripts/gcs_storage.py`가 `.env`의 `GCS_BUCKET_NAME`/`GOOGLE_APPLICATION_CREDENTIALS`를 씁니다).
3. **"문서관리" 탭 화면 재설계(6차, 2026-09-13)**: 업로드/다운로드/문서분리/문서통합
   네 기능이 한 화면에 뒤섞여 헷갈린다는 피드백에 따라, 아래 5개 섹션으로 뚜렷이
   구분했습니다(위→아래 순서, 신청건 선택 정보 바로 아래부터):
   - **⬆ 일괄 업로드**: 매뉴얼/절차서/양식/지침서 완성본은 물론 내용본까지, 여러
     파일을 한 번에 선택해 올리면 파일명에서 표시기호를 자동 인식해 등록합니다
     (자동 인식 실패 시 직접 문서종류 지정 가능). 예전 "완성본 일괄 업로드"를
     대체·확장한 것으로, 매뉴얼/절차서에만 한정하지 않습니다.
   - **⬇ 일괄 다운로드**: 이 신청건에 저장된 문서 전체(또는 선택한 구분만, 내용본
     포함 여부 선택)를 zip 하나로 받습니다(신규).
   - **✂ 문서분리**: 통합 HWP 파일 하나만 올리면, 이 신청건에 이미 등록된 문서
     목록(코드+명칭)에서 "가상 분리기준표"를 자동 생성해 문서별로 잘라냅니다 —
     분리기준표 xlsx를 따로 준비할 필요가 없습니다. 자세한 내용은 아래
     "문서분리 사용 시 참고" 참조.
   - **🔗 문서통합**: 현재 신청건의 매뉴얼/절차서 완성본들을 모아 `document_integrated`
     레코드를 만들고, `hwp_merge.py`로 실제 HWP 병합까지 시도합니다(실패하면
     자동으로 "병합 대기" 상태로 남음 — 아래 "문서통합 재검토 결과" 참조, 여전히
     미검증 초안입니다).
   - **개별 문서 처리(예외용)**: 문서 1건만 급히 올리거나 받을 때 쓰는 보조 기능으로
     맨 아래로 옮겼습니다. 평소엔 위 일괄 업로드/다운로드를 쓰세요.

   (문서분리는 한 번 화면에서 뺐다가, "분리기준표를 매번 준비하는 부담"이라는 실제
   문제만 없애는 방식 — 즉 기준표 자동 생성 — 으로 다시 넣은 것입니다. 손으로 만든
   분리기준표.xlsx를 그대로 쓰고 싶다면 `scripts/hwp_split.py`의 `split_hwp_file()`
   (기존 방식)이 그대로 남아있으니 필요시 화면에 다시 연결할 수 있습니다.)
4. **"프로젝트명" 표시(6차)**: 신청건 헤더의 "프로필" 라벨을 "프로젝트명"으로
   바꾸고, 내용도 "{신청건 번호}-{프로필코드}"(예: "1-qM18c04") 형태로 바꿨습니다 —
   그 신청건의 정식 명칭입니다. 실제 저장 경로(GCS)에 쓰이는 `project_no` 값
   자체는 그대로입니다. "Company/Sample name" 라벨도 실제 회사 등록건이면
   "Company name", 샘플 등록건이면 "Sample name"으로 상황에 맞게 바뀝니다.
5. **"분류문서 보기" 탭 신설**: 문서종류 하나를 고르면 그 문서를 만든 모든 신청건을
   한 화면에서 보는 대장(원장) 화면입니다. 매뉴얼/절차서는 규격 필터+검색형 선택,
   지침서는 중분류→세분류 2단계, 양식은 관련 절차서→하위 양식 2단계로 좁혀갑니다.
6. **"O매뉴얼/절차서 O양식" 토글**: "문서관리" 탭의 문서 목록에서 매뉴얼·절차서
   묶음과 양식을 전환해서 볼 수 있습니다.
7. **"O매뉴얼 O절차서 O양식 O지침서" 4분류 토글**: "분류문서 보기" 탭에서 4가지를
   각각 따로 봅니다(탭1과 달리 매뉴얼/절차서가 분리되어 있습니다).
8. **Original 번호화**: `sample_original` 마스터 테이블 신설. "사용자 등록"에서는
   번호(+원본명)로 고르거나 새로 등록하고, 화면 어디서나 Original은 번호로만
   표시됩니다 — 전체 이름은 [1. 기준정보 조회 → sample_original(Original 현황)]에서
   확인할 수 있습니다.
9. **양식번호(form_seq_no)**: `document_individual.form_seq_no`로 신설 — 마스터
   `doc_code`(예: F612e-01, 중복 없음)와 별개로, 신청건(회사/샘플)별로 양식을 생성할 때
   매기는 일련번호(중복 가능)입니다. "문서관리" 탭에서 양식 완성본을 올릴 때 함께
   입력할 수 있습니다.

## 문서분리 사용 시 참고

- **분리기준표 xlsx가 필요 없습니다(6차 재도입 핵심 변경).** 이 신청건에 이미
  등록된 문서 목록(코드+명칭, 화면 위쪽 표와 같은 순서)에서 "가상 분리기준표"를
  자동으로 만들어 씁니다(`hwp_split.build_virtual_tasks_from_doc_list()`). "유지
  끝구간"(다음 항목 코드 직전 / 마지막 항목은 "문서 끝")도 자동 계산됩니다.
  핵심 분리 엔진(`hwp_splitter.py`, pyhwpx로 앵커 텍스트 찾아 블록 선택→저장)은
  이전과 완전히 동일하며 손대지 않았습니다.
- 통합본 안의 실제 문서 순서가 이 자동 생성 순서와 다르면 엉뚱한 구간이 잘릴 수
  있습니다 — [✂ 문서분리] 섹션의 편집 가능한 표에서 "순서"를 고치거나, 이번엔
  뺄 문서는 "포함" 체크를 해제하세요.
- 찾기 기준 텍스트(anchor_mode)는 "문서명 우선 + 실패시 코드"(both, 기본값) /
  "문서명/양식명만"(title) / "코드만"(code) 중 고를 수 있습니다. 처음 몇 건은
  결과 표의 "실패/수동확인필요" 목록을 꼭 확인하시고, 안 되면 anchor_mode를
  바꿔가며 시도해보세요.
- 분리에 성공한 파일은 [⬆ 일괄 업로드]와 같은 방식으로 곧바로 이 신청건의
  완성본으로 GCS에 저장되고 `document_individual`에 등록됩니다(파일을 따로
  내려받아 다시 업로드할 필요 없음).
- 손으로 준비한 분리기준표.xlsx를 그대로 쓰고 싶은 경우를 위해 기존 방식
  (`hwp_split.split_hwp_file()`)도 코드에는 남겨뒀습니다 — 화면에는 연결하지
  않았으니 필요하면 알려주세요.

## 문서통합 재검토 결과 (2026-09-13, "3플랫폼 제작" 대화록 반영)

말씀해주신 대화록(hwp_splitter.py가 만들어지던 과정)을 참고해서 `scripts/hwp_merge.py`를
다시 검토·재작성했습니다. 바뀐 점:

1. **이전 초안의 `insert_file()` 우선 시도를 없앴습니다.** 검증된 실물 코드
   (`hwp_splitter.py`)의 `HwpEngine`에는 그 메서드가 전혀 등장하지 않아서, 근거 없이
   "우선 방법"으로 놓는 건 적절하지 않다고 판단했습니다. (완전히 빼지는 않고, 있으면
   시도만 해보고 실패해도 무해하게 바로 다음 방법으로 넘어가도록 남겨뒀습니다.)
2. **기본(사실상 주) 방법을 검증된 실물 코드와 완전히 동일한 API 호출로만 구성**했습니다
   — `open`/`MoveDocBegin`/`MoveDocEnd`/`get_pos`/`select_text`/`Copy`/`Paste`/`FileNew`/
   `save_as`/`Quit`. "문서 전체 선택" 부분은 split 코드의 fallback 선택 로직과 완전히
   같은 패턴이고, 대상만 "찾은 구간"이 아니라 "문서 전체"로 바뀐 것뿐입니다.
3. **그래도 "검증됐다"고는 할 수 없습니다.** split 프로그램은 "한 파일을 열어 구간을
   잘라 저장"만 반복했지, "여러 파일을 순서대로 복사해서 하나의 누적 문서에 이어
   붙이는" 조합은 그 프로그램에서 한 번도 실행된 적이 없습니다. 개별 API 호출은 전부
   실물 코드 그대로지만, 이렇게 조합했을 때 실제로 서식이 안 깨지고 동작하는지는
   이번이 처음 확인하는 것입니다 — **반드시 파일 2~3개만으로 먼저 테스트**해주세요.
4. **쪽번호 연속성은 미해결**입니다. 대화록에 "상용구 삽입으로 페이지 번호 필드
   문제를 해결했다"는 내용이 있는데, 그 상용구 자체(실제 코드)는 전달받지 못해서
   그대로 이식하지 못했습니다. 병합 후 쪽번호가 꼬일 가능성이 있습니다.

**일괄 업로드**(원래 "완성본 일괄 업로드")는 6차에서 "문서통합" 섹션 안이 아니라
화면 맨 위쪽의 독립된 [⬆ 일괄 업로드] 섹션으로 옮겼고, 매뉴얼/절차서 완성본뿐 아니라
양식/지침서 완성본과 내용본까지 전부 처리하도록 넓혔습니다. 파일명에서 표시기호(예:
`qM0000P410_조직의상황관리.hwp` → `P410`, `P-530(조직관리).hwpx` → `P530`)를 자동
인식해 등록하고, 인식 못 한 파일은 직접 문서종류를 지정할 수 있습니다. 등록된 완성본은
그대로 [🔗 문서통합 실행]에서 사용됩니다.

**참고용으로 요청드립니다**: 말씀하신 "9기타_문서(절차서지침서)분류", "_2", "_3" 폴더를
찾아보려고 이 PC(win11-01)의 바탕화면/문서/`class2605` 프로젝트 폴더 몇 군데를
살펴봤는데, 이름이 일치하는 폴더를 찾지 못했습니다(폴더 접근 권한이 없는 상태에서는
이름만 보이고 안의 파일은 볼 수 없어서, 짐작으로 여러 곳을 더 뒤지기보다는 여쭤보는
게 나을 것 같았습니다). 그 폴더들의 정확한 경로를 알려주시면 접근 권한을 요청드리고,
실제로 수작업 병합/분리를 하신 샘플(통합본 1개 + 그걸 구성한 개별원본 몇 개)을 살펴서
쪽나눔·머리말 처리가 실제로 어떻게 되어 있는지 확인한 뒤 `hwp_merge.py`를 더 다듬을 수
있습니다. 경로를 모르시면 대표 파일 몇 개만 이 대화에 첨부해주셔도 됩니다.
